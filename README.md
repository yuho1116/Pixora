# Pixora

Pixora —— 上传 · 分享 · 简单完成

Pixora 是一款轻量级的图片上传与链接分享工具：把图片变成链接，让图片分享更简单。

无需注册登录，打开即可上传图片，自动生成图片直链，一键复制分享。

## 产品定位

Pixora 不仅仅是一个图片托管工具，更是一个轻量级的图片链接生成与分享工具。

核心理念：**把图片变成链接，让图片分享更简单。**

- 图片变链接，分享更轻松
- 不必反复发送图片附件
- 一个链接，轻松跨平台分享
- 截图、照片、教程图片，都能快速分享
- 多图上传，统一管理
- 灵活设置图片保存期限
- 简单几步，完成图片分享

## 主要功能

- 支持 JPG、JPEG、PNG、WebP、GIF，单张最大 10MB，单次最多 10 张
- 系统文件选择器选图，桌面端支持拖放上传
- 多张图片依次上传，显示真实上传进度
- 保存期限：1 小时 / 24 小时 / 7 天 / 30 天 / 永久保存（首页与设置页均可切换，自动保存）
- 自动清除 EXIF、GPS 等隐私元数据（客户端对 JPEG/PNG 解码重编码清除，服务端上传时也会自动清除）
- 上传完成后生成真实图片直链，可复制单张链接、一键复制全部链接
- 查看图片（全屏，支持缩放）、删除图片（删除后链接立即失效）、上传失败提示与重试
- 上传失败时显示真实原因（服务器状态码、网络或证书问题等），网络抖动导致的连接类失败会自动重试一次
- 界面全部为简体中文（品牌名 Pixora 与技术标识保留英文），无登录、无社交、无会员、无广告

## 使用场景

- **替代图片附件发送**：上传图片后生成链接，通过短信或聊天消息发给对方，对方点击链接即可查看图片
- **AI 图片分享**：在 ChatGPT 等 AI 对话平台需要引用图片时，可以尝试使用 Pixora 生成图片链接，减少重复上传的麻烦。不同 AI 平台对外部图片链接的读取支持不同，不保证所有平台都能直接识别
- **跨平台图片分享**：将图片链接发送到微信、QQ、Telegram、WhatsApp 等支持链接的平台
- **论坛与社区发图**：为论坛、博客、社区和技术交流提供图片链接；服务端提供真正的图片直链，也可用于 Markdown 和网页嵌入
- **工作与学习分享**：方便分享教程截图、错误提示、设计稿、作业图片和操作说明
- **截图快速传递**：电脑或手机截图上传后生成链接，方便远程协助、技术支持和问题反馈
- **临时图片分享**：通过设置图片有效期满足临时分享需求，减少图片长期保留的顾虑
- **多图批量分享**：支持多张图片上传，方便一次性整理和分享多张图片
- **图片链接收藏**：生成链接后可以保存、复制和再次使用；Pixora 是分享工具，不是可靠的永久备份服务，请勿将它作为图片的唯一备份

## 使用流程

选择图片 → 开始上传 → 生成链接 → 复制分享

1. 点击「选择图片」（或把图片拖放到上传区域）
2. 选择保存期限，点击「开始上传」
3. 上传完成后复制链接，发给需要的人即可

## 图片保存期限

以实际服务端能力为准。上传时可选择 1 小时、24 小时、7 天、30 天或永久保存，到期后服务端自动删除，链接随之失效。选择「永久保存」表示服务端不设过期时间，但这不等于永久备份承诺：图片保存在第三方服务端，链接的有效性取决于该服务的持续可用。

## 技术架构

- Flutter 开发的独立应用，不使用 WebView，不嵌入任何网站
- 图片托管使用 Relavo 的真实接口（已实测验证）：
  - 上传：`POST https://relavo.net/api/upload`，multipart 字段 `expiry` + `files`（一次一张），返回 `image_urls`（直链 `https://relavo.net/i/xxx`）、`urls`（查看页）、`image_ids`、`delete_tokens`、`expires_at`
  - 删除：`POST https://relavo.net/api/delete`，字段 `image_id` + `token`
  - 直链、删除均已用真实图片实测通过（上传成功、直链可访问、删除后返回 404）
- 本项目没有自建后端，不保存账号与图片数据；上传记录只保留在应用当前运行期间

## 注意事项与已知限制

- 图片上传与存储依赖 Relavo 服务端；该服务不可用时无法上传，Pixora 不承诺服务的持续可用
- 图片仅通过链接访问，不会公开列出；但拿到链接的人都能查看，请勿上传敏感图片
- 上传记录与删除凭证只保留在应用当前运行期间；退出应用后，已上传图片无法再从应用内删除（链接仍按所选期限有效）
- 暂不支持二维码分享
- 客户端仅对 JPEG/PNG 做 EXIF 清除重编码；GIF/WebP 由服务端在上传时自动清除元数据
- 发布版目前使用调试签名（debug signing config），适合侧载安装；如需上架应用商店，请配置自己的正式签名
- 选图时不会在手机相册中产生新文件：1.0.0 已关闭选图插件默认的图片压缩行为（旧版会在公共 Pictures 目录生成一张压缩图，该问题已修复）

## 构建说明（环境备注）

在 Flutter 3.50 + compileSdk 36 环境下编译时，以下两个插件的 pub 缓存副本需要把 compileSdk 改高，否则 AAR 元数据检查会失败：

- `desktop_drop 0.6.1`：`android/build.gradle` 中 `compileSdk 33` → `34`
- `file_picker 8.3.7`：`android/build.gradle` 中 `compileSdk 34` → `36`

位置在 `~/.pub-cache/hosted/pub.dev/<插件名>-<版本>/android/build.gradle`。改完后重新执行 `flutter build apk --release` 即可。重新 `flutter pub get` 不会覆盖该修改，只有升级插件版本或执行 `flutter pub cache repair` 后才需重新改。
